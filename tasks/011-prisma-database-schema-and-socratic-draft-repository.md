# Task 011 — Prisma Database Schema And Socratic Draft Repository

## Status

Complete.

## Goal

Add the first database schema and host-owned repository foundation for Socratic Draft conversation persistence.

## Scope

- Choose the database toolkit for the project.
- Add Prisma schema/configuration for PostgreSQL.
- Define initial Socratic Draft entry and conversation message tables.
- Generate the initial SQL migration with Prisma tooling.
- Add root/package scripts for Prisma generation, validation, and migrations.
- Add a Prisma-backed adapter that satisfies the product-owned `EntryStore` port.
- Keep product packages independent of Prisma and database implementation details.
- Add contract-focused tests for the adapter behaviour.
- Wire the API to use Prisma persistence when `DATABASE_URL` is set, with in-memory storage as the no-database fallback.
- Document the strict generated-migration workflow.

## Out Of Scope

- Owner auth.
- Real AI calls.
- Applying migrations to a real database.
- Database provisioning.
- Demo ephemeral-mode enforcement.
- Usage limits.
- Publishing flow.
- Editor UI changes.
- Hand-written or manually edited migration SQL.

## Definition Of Done

- Prisma is installed and configured in `packages/db`.
- Prisma schema defines Socratic Draft entries and conversation messages.
- Initial SQL migration is generated by Prisma tooling and committed as an artifact.
- Migration workflow explicitly forbids hand-editing migration files.
- `packages/db` exports a Prisma-backed Socratic Draft `EntryStore` adapter.
- API route composition can use the Prisma-backed adapter when `DATABASE_URL` exists.
- Product code does not import Prisma or `packages/db`.
- `pnpm db:validate`, `pnpm db:generate`, `pnpm test`, and `pnpm typecheck` pass.

## Validation

```txt
pnpm db:validate
pnpm db:generate
pnpm test
pnpm typecheck
```
